Documented that rate-limit and request-queue limits are enforced **per worker**, not per server: the rate limiter is shared only in thread mode (independent copies on process/subinterpreter builds), and the request queue is per worker in every mode. With `workers > 1` the effective aggregate is `limit x workers` (per-IP `rate x workers`, shed depth `max_depth x workers`). Clarified in the backpressure docs, the `core-contract` doc, and the `ServerConfig`/`TokenBucket`/`RequestQueue` docstrings.
