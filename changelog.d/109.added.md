The server now logs a startup INFO line stating the **effective aggregate** of backpressure limits across workers: for rate limiting, `rate req/s per IP per worker x N workers = ~aggregate` on process/subinterpreter builds (or "shared across workers; aggregate = configured" in thread mode), and for request queueing, `max depth D per worker x N workers = ~aggregate queued` (the queue is per worker in every mode). This makes the `limit x workers` multiplier visible to operators at startup.
